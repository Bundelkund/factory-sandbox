# Design Issue #113 (v2)

> Architektur-Loop (`anthropic/claude-opus-5.5`, Runde 1); ein Pruefer anderer Modellfamilie nimmt es ab, bevor Dev beginnt. Dev folgt diesem Weg.

## Loesungsweg

Neue Datei canary/review-probe/seite.py anlegen, die oben import html (Standardbibliothek) ausfuehrt und die Funktion ueberschrift(name) definiert. Die Funktion gibt '<h1>' + html.escape(str(name)) + '</h1>' zurueck, ohne Zeilenumbruch, und auf Modulebene steht kein print und keine Ausgabe. ueberschrift('Hallo') liefert damit unveraendert <h1>Hallo</h1>, waehrend Sonderzeichen wie < oder & sicher maskiert werden. Sonst keine Datei aendern.

## Dateien

- `canary/review-probe/seite.py`: Neue Datei mit import html und der Funktion ueberschrift(name), die den mit html.escape maskierten Namen in <h1>...</h1> eingebettet zurueckgibt.

## Blast-Radius

nichts; neue, isolierte Datei ohne Aufrufer im Repo, keine Daten betroffen

## Risikoklasse

gruen · rote Zone: keine

## Abweichung von v1

Die Fehlerausgaben der roten Dev-Runden sind leer, ein konkreter Fehler ist also nicht belegt. v1 bettete den Namen ungeprueft per f-String ein, was ein Review als HTML-Injection bemaengeln kann. v2 wandelt den Namen mit str() um und maskiert ihn mit html.escape aus der Standardbibliothek. Er baut den String per Verkettung statt per f-String. Das Ergebnis fuer 'Hallo' und damit die AK bleiben gleich.
